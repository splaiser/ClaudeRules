# Многошаговая задача

## Старт
1. Создай `.claude/work/<задача>.md`: цель, критерий готовности (какая команда
   должна пройти), список шагов с `[ ]`. `git check-ignore -q .claude/work/x`
   вернул ненулевой код → допиши `.claude/work/` в файл
   `$(git rev-parse --git-path info/exclude)` (локально, в коммиты не попадает).
   Затем `bash ~/.claude/skills/review/gate.sh --start`.
2. Выпиши стоп-условия. По умолчанию — только эти:
   - действие необратимо или трогает данные/конфиг вне задачи;
   - проверка не проходит после 3 попыток исправить;
   - требования противоречат коду так, что выбор меняет результат;
   - внешняя система (API, БД, CI) вернула ошибку.
   Во всех остальных случаях не останавливайся и не спрашивай «можно ли».

## Ход работы
- `[x]` ставится только с доказательством рядом: команда + её итог одной
  строкой. «Сделал» без вывода проверки — не закрытие.
- Условный шаг, который не понадобился: `[x] SKIP: <причина>`.
- Проверка вернула пусто/ошибку → не подменяй её другой молча. Запиши, что
  не сработало, и чини или явно помечай замену.
- Цикл до нуля: исправил → перепроверил. Одна волна правок ничего не гарантирует.
- Провал шага → максимум 2 альтернативных подхода, потом стоп с обеими причинами.

## Запись во внешние системы
- Сначала найти по стабильному ключу, потом update-or-create. Никаких слепых вставок.
- После записи прочитай состояние обратно и сверь.

## Финал
1. `grep -c "\[ \]" .claude/work/<задача>.md` → должно быть 0.
2. Полный набор проверок из CLAUDE.md проекта (типы, линт, тесты).
3. Ревью по скиллу `review` против критерия готовности (промежуточные ревью
   по ходу задачи уже учтены — проверяется только новое). Правь пункты
   «не выполнено» и находки уровня «критично»; «не могу проверить» назови в итоге.
4. Если в задаче были `ponytail:`-упрощения — они перечислены в итоге.
5. Итог пользователю: 3–5 строк — что сделано, чем проверено, что осталось.
   Частичный провал называется прямо, не прячется в «почти готово».
6. Новая ловушка проекта, найденная по ходу → урок через
   `~/.claude/skills/rules-review/lesson.sh` и упоминание в итоге. CLAUDE.md
   не правь: в правила уроки переносит `/rules-review`.
