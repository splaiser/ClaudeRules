# Ревью без лишних прогонов

## Когда
Перед тем как считать нетривиальную задачу готовой — и только после `PASS` от
`test-runner`: код с падающими проверками не ревьюится.

## Порядок
1. `bash ~/.claude/skills/review/gate.sh` в корне проекта.
2. `verdict: skip` → reviewer не вызывать. В итоге одна строка:
   «ревью пропущено: <reason>». Если по смыслу правка важнее цифр (логика денег,
   прав, данных в файле, не попавшем в зоны риска) — всё равно вызови reviewer и
   назови причину. Обратное — пропустить при `run` — нельзя.
3. `verdict: run` → reviewer получает команду из строки `diff:`, критерий
   готовности и файлы из `focus:` — их проверить первыми.
   `size=big` → не вставляй дифф в запрос: дай команду, `focus` и список самых
   больших файлов; остальное reviewer читает сам по необходимости.
4. После ответа reviewer: `bash ~/.claude/skills/review/gate.sh --mark ok`
   (нет находок) или `… --mark findings`. Базой становится снимок, который проверялся;
   исправления по находкам попадут в следующую дельту.
5. Пропущенные мелкие правки не отмечаются: они копятся и уходят в ревью,
   когда вместе перевалят порог.

Истории ревью в ветке нет → база: для ветки от основной — вся ветка, иначе —
незакоммиченное. В начале большой задачи — `gate.sh --start`. Проверить
от явной точки — `gate.sh --base <коммит>`.

## Что измеряет гейт
| Признак | Как | Зачем |
|---|---|---|
| Новизна | дифф между снимком прошлого ревью и текущим | уже проверенное не проверяется снова |
| Значимые строки | добавленные + удалённые без пробелов и пустых строк | форматирование — не изменение |
| Файлы кода | всё, кроме документации и lock-файлов | тексты вычитывает `human-text`, не reviewer |
| Зоны риска | путь по шаблону: авторизация, деньги, ключи, миграции, контракты, CI, деплой | малая правка там дороже большой в другом месте |
| Зависимости | изменён манифест пакетов | риск цепочки поставок |
| Размер | ≥ 400 строк или ≥ 15 файлов | большой дифф — ревью по командам и `focus`, не вставкой |

Пороги и шаблоны — в начале `gate.sh`.

## Калибровка
Каждое ревью пишется в `~/.claude/review-log.tsv`: дата, проект, ветка, признаки,
`ok` или `findings`. Когда в журнале 30+ строк после последней калибровки,
`/rules-review` предлагает одну правку порогов:
- больше 80% ревью мелких дельт без зон риска (до ~60 строк) дали `ok` →
  поднять `SKIP_LINES`;
- в уроках есть ошибки, пропущенные из-за `skip`, → опустить порог или
  расширить `RISK_RE` путём из урока.
