# Подключение проекта к базе

1. Прочитай `~/.claude/CLAUDE.md`, CLAUDE.md проекта (если есть) и `.claude/rules/`.
2. Определи сам по файлам проекта: стек, менеджер пакетов, форматтер, команды
   типов/линта/тестов/сборки (package.json, pyproject, Makefile и т.п.).
   Быстрые команды (типы, линт) запусти один раз; для тестов проверь, что скрипт есть.
3. Собери CLAUDE.md проекта только из:
   - `## Команды` — проверенные команды из шага 2;
   - стек и его строгость (например, TypeScript strict);
   - особенности проекта, которые не выводятся из кода;
   - явные исключения из базы: «В этом проекте вместо <правило базы> — <правило>».
4. Удали из проектного файла всё, что дублирует базу. Противоречие базе без
   пометки исключения — не решай сам: покажи обе формулировки и спроси.
5. Правила, которые нужны только для части файлов, вынеси в
   `.claude/rules/<тема>.md` с фронтматтером `paths`.
6. Посчитай, что грузится в каждую сессию: CLAUDE.md, `@`-импорты, `.claude/rules/`
   без `paths`. Документ больше ~2 тыс. токенов (концепция, спецификация) —
   предложи убрать из автозагрузки и читать по требованию.
7. graphify. Если есть `graphify-out/`: проверь, что в CLAUDE.md одна секция
   graphify (её пишет `graphify claude install`), без дублей, и что стоят git-хуки
   (`graphify hook status`, иначе предложи `graphify hook install`). Строку «после
   правок запускай `graphify update .`» убери — граф обновляют git-хуки.
   Если `graphify-out/` нет — не предлагай его для небольших проектов.
8. Покажи дифф и итоговый размер. Записывай только после подтверждения.

Цель — до ~40 строк. Не добавляй правил, которых нет в исходном файле или в
находках шага 2.
