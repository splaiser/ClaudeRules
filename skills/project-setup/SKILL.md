# Подключение проекта к базе

## 1. Замер
Запусти `bash ~/.claude/skills/project-setup/measure.sh` в корне проекта.
Строки `langs`, `web`, `ui`, `bots`, `agents`, `crypto`, `engine`, `bin` —
для раздела 4, `size` — для раздела 5.
Вердикт `size`:
- `SMALL` — только базовая версия, graphify не предлагать;
- `BORDERLINE` — покажи цифры и спроси, нужен ли graphify;
- `LARGE_CODE` / `LARGE_DOCS` — предложить graphify (раздел 5).
Если `graphify-out/` уже есть — это ветка `LARGE_*` независимо от вердикта.

## 2. Разведка
1. Прочитай `~/.claude/CLAUDE.md`, CLAUDE.md проекта (если есть), `.claude/rules/`.
2. Определи по файлам: стек, менеджер пакетов, форматтер, команды
   типов/линта/тестов/сборки. Быстрые (типы, линт) запусти один раз;
   для тестов проверь, что скрипт есть.
3. Посчитай, что грузится в каждую сессию: CLAUDE.md, `@`-импорты,
   `.claude/rules/` без `paths`. Документ больше ~2 тыс. токенов — предложи
   убрать из автозагрузки и читать по требованию.

## 3. CLAUDE.md проекта
Только:
- `## Команды` — проверенные команды из разведки;
- стек и его строгость;
- особенности проекта, которые не выводятся из кода;
- явные исключения из базы: «В этом проекте вместо <правило базы> — <правило>».

Всё, что дублирует базу, — убрать. Противоречие базе без пометки исключения —
не решай сам: покажи обе формулировки и спроси. Правила для части файлов —
в `.claude/rules/<тема>.md` с `paths`. Цель — до ~40 строк.

`.gitignore`: `.claude/work/` (рабочие чек-листы `long-task`). Журнал уроков
лежит вне репозитория (`~/.claude/lessons/`) — его добавлять не нужно.

Покажи дифф и размер. Записывай только после подтверждения.

## 4. Плагины по проекту
1. Прочитай `~/.claude/skills/project-setup/plugins.md` и по выводу замера
   составь список: плагин, почему нужен, что ещё требуется (бинарник, python, java).
   Нет признаков — плагины не предлагать.
2. Список показывается вместе с диффом раздела 3 и подтверждается одним разом.
3. После подтверждения для каждого:
   `claude plugin install <плагин>@<маркетплейс> --scope project`
   (пишет в `.claude/settings.json` проекта). Сторонний маркетплейс —
   сначала `claude plugin marketplace add <репозиторий>` из каталога.
   Бинарник LSP ставь до плагина. Команда не сработала или `claude=no` —
   не обходи, дай пользователю `/plugin install <плагин>@<маркетплейс>`.
   Игровые движки — только рекомендация со ссылкой, ничего не ставить.
4. В конце напомни: `/reload-plugins`.

## 5. graphify (только ветка LARGE_* или согласие на BORDERLINE)
Каждый пункт с побочным эффектом — только после подтверждения пользователя.
1. `graphify --version`. Нет — нужен Python 3.10+ и `uv tool install graphifyy`
   (пакет с двумя y). Установку не выполняй сам — покажи команду.
2. Проверь, что основной язык проекта graphify разбирает (список в его README).
   Нет (например, 1С `.bsl`/`.os`) — граф по коду будет почти пустым: при
   `LARGE_CODE` graphify не ставить; при `LARGE_DOCS` — только ради документов.
3. Граф нет → построить:
   - `LARGE_CODE`: `graphify extract . --code-only` — локально, без затрат токенов;
   - `LARGE_DOCS`: `/graphify .` — документы идут через модель, это стоит токенов;
     назови это до запуска.
4. `graphify claude install` — пишет свою секцию в CLAUDE.md и хук-подсказку.
   Запускай после раздела 3 (CLAUDE.md проекта), затем проверь, что секция graphify одна.
   Строку «после правок запускай `graphify update .`» убери — это делают git-хуки.
5. `graphify hook status` → нет хуков → `graphify hook install`.
6. `.gitignore`: `graphify-out/cost.json`.
7. Документ, убранный из автозагрузки в разведке, теперь доступен через
   `graphify query` / `explain` — упомяни это в CLAUDE.md одной строкой.

## 6. Итог
3–5 строк: вердикт с цифрами, что изменено в CLAUDE.md (размер до/после),
какие плагины поставлены и каких не хватило, что с graphify.
