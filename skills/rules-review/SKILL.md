# Разбор уроков

Цель — одна правка правил за запуск, подтверждённая журналом. Не перестройка правил.

## 1. Сбор
1. Журнал проекта: `bash ~/.claude/skills/rules-review/lesson.sh --path`.
   Журналы всех проектов — `~/.claude/lessons/*.md` (без `.archive.md`).
2. Необработанных записей меньше 3 во всех журналах — назови число и переходи
   сразу к разделу 8: для правки правил данных мало.
3. Прочитай действующие правила: `~/.claude/CLAUDE.md`, CLAUDE.md проекта,
   `.claude/rules/`, скиллы, к которым относятся записи.

## 2. Сортировка записей
Каждую необработанную запись отнеси к одному:
- **урок** — повторяемая ошибка, из которой выходит правило;
- **шум: разовое** — уточнение одной задачи, правилом не станет;
- **шум: дубль** — повтор уже закрытого правилом, и правило соблюдалось;
- **шум: неверно** — агент понял поправку не так.

## 3. Одна проблема
1. Сгруппируй уроки по причине, а не по формулировке. Для каждой группы —
   число записей, проекты, даты первой и последней.
2. Возьми одну группу: самую частую; при равенстве — где ошибка дороже
   (переделка, потеря данных, прод). Остальные уроки остаются в журнале на потом.
3. Правило про это уже есть, а ошибка повторяется после его появления → правь
   формулировку существующего правила, новое не добавляй.

## 4. Уровень правила
- Та же ошибка в нескольких проектах или верна для любого → база. Правка базы
  действует во всех проектах — назови это. Правь в репозитории базы: путь —
  `readlink ~/.claude/CLAUDE.md`; в режиме копии спроси путь. Напомни закоммитить.
  Правило базы заменено или убрано → строка в `skills/project-setup/retired.md`:
  по ней `/project-setup` найдёт старые копии в проектах.
- Только этот стек или проект → CLAUDE.md проекта или `.claude/rules/<тема>.md`
  с `paths`.
- Нужно для одного вида задач → скилл: он не грузится в каждую сессию.

## 5. Предложение
Покажи:
- группу: N записей, проекты, даты, 1–2 цитаты;
- дифф правки в формате «правило — почему»;
- размер файла до и после; противоречие с другим правилом — обе формулировки;
- чем проверить: пункт `checks.md` базы или прошлая ситуация из журнала.

Записывай только после подтверждения.

## 6. Архив и счётчики
После решения пользователя перенеси обработанные записи в `<журнал>.archive.md`
с пометкой в конце строки: `→ правило ГГГГ-ММ-ДД`, `→ шум: разовое|дубль|неверно`
или `→ отклонено`. Уроки из групп «на потом» остаются в журнале.
В строке `<!-- rules-review: … -->` журнала: `запусков` +1, `записей` + число
разобранных, `шум` + число шумовых.

## 7. Замер шума (каждый 3-й запуск)
Когда `запусков` кратно 3, посчитай долю шума по счётчикам всех журналов.
- Больше 30% → предложи одну правку правила записи уроков в базовом CLAUDE.md
  (уже формулировка, пример того, что не урок) — отдельно от правки шага 5.
- 30% и меньше → подход оставить.
Результат запиши в счётчик: `замер=ГГГГ-ММ-ДД шум=N% оставлено|изменено`.

## 8. Калибровка ревью
В `~/.claude/review-log.tsv` 30+ строк после последней калибровки →
выполни раздел «Калибровка» скилла `review` и допиши в журнал ревью строку
`# калибровка ГГГГ-ММ-ДД: <решение>`.

## 9. Итог
2–4 строки: что изменено и где, сколько записей разобрано и сколько из них шум,
результат замера, если он был.
