# claude-base

Общие правила, скиллы, субагенты и хуки Claude Code для всех проектов.

## Установка и обновление

    git clone <url> ~/claude-base
    bash ~/claude-base/install.sh          # Windows без Developer Mode: COPY=1 bash install.sh

Обновление: `git pull && bash install.sh`. В режиме симлинков правки в репозитории
действуют сразу, установщик нужен только при добавлении новых файлов или хуков.

## Слои

1. `~/.claude/` — эта база (грузится во всех проектах первой).
2. `<проект>/CLAUDE.md` и `<проект>/.claude/` — только команды, стек, особенности
   и явные исключения из базы. Подключить старый или новый проект — `/project-setup`.

## Состав

- `CLAUDE.md` — поведение, подход к задачам, честность, экономия контекста.
- `skills/long-task` — дисциплина многошаговых задач (грузится по требованию).
- `skills/human-text` — вычитка текстов на машинный стиль.
- `skills/project-setup` — подключение проекта к базе (только вручную): замер
  проекта (`measure.sh`), чистка CLAUDE.md, плагины по проекту по каталогу
  `plugins.md` (LSP, безопасность, UI, крипто, Claude Agent SDK, геймдев, 1С),
  graphify для больших. Повторный запуск после изменений базы сверяет проект
  с ней: дубли, противоречия и старые копии правил из `retired.md`.
- `skills/review` — когда и на какой дифф звать `reviewer`: скрипт `gate.sh`
  считает только новое с прошлого ревью и пропускает незначительное.
- `skills/rules-review` — журнал уроков (`lesson.sh`) и его разбор (только вручную):
  одна правка правил за запуск, замер шума, калибровка порогов ревью.
- Глобально установщик ставит плагины Context7 (актуальная документация библиотек)
  и ponytail (на него ссылаются правила и reviewer).
- `agents/test-runner` (Haiku), `agents/reviewer` — вывод и проверки вне основного контекста.
- `hooks/stop-review.sh` — хук Stop: напоминает о ревью, если гейт видит непроверенные
  изменения выше порога. Ставится в `~/.claude/claude-base-hooks/`, выключается
  переменной окружения `CLAUDE_BASE_HOOKS=off`.
- `settings.base.json` — разрешения (`allow`, `ask`, `deny`); сливается с
  `~/.claude/settings.json`. Правило, убранное из базы, установщик убирает и оттуда
  (список добавленного — `~/.claude/claude-base.permissions.json`).
- `checks.md` — проверки самой базы после её правок (не устанавливается).
- `tools/session-stats.py` — куда уходят токены в ваших сессиях: кеш, выход, вывод
  инструментов, доля русского текста, перезаписи кеша после пауз. Читает
  `~/.claude/projects/`, модель не вызывает (не устанавливается; нужен Python 3).

## Журнал уроков

Когда вы поправляете агента в том, что повторится, он вызывает `lesson.sh`, и
урок ложится в `~/.claude/lessons/<проект>.md` — вне репозитория проекта, в его
коммиты не попадёт. Для бэкапа и синхронизации между машинами задайте
`CLAUDE_LESSONS_DIR` — путь к клону своего приватного репозитория (не делайте
git из всего `~/.claude`: там учётные данные и истории сессий).

Второй источник уроков — встроенная автопамять Claude Code: поправки, которые
агент запомнил сам (`~/.claude/projects/*/memory/`, тип `feedback`). `/rules-review`
читает и её, так что урок не теряется, даже если агент забыл вызвать `lesson.sh`. На 10 необработанных записях агент предложит `/rules-review`: самая
частая ошибка становится одной правкой правил, разобранное уходит в
`<проект>.archive.md`. Каждый третий разбор меряет долю шума в журнале и
предлагает поправить правило записи, если шума больше 30%.

## Ревью

`reviewer` — тяжёлая проверка, поэтому решение о ней принимает скрипт, а не
модель: `skills/review/gate.sh` сравнивает рабочую копию со снимком прошлого
ревью ветки. Вызов тоже не зависит от памяти модели: хук Stop запускает гейт
при каждой остановке агента и напоминает о ревью один раз на состояние кода. Нет изменений, только текстовая документация (`.md`, `.txt`; спецификации
`.yaml`/`.json`/`.proto` считаются кодом) или пробелы, мелкая правка вне
зон риска → ревью пропускается (мелочь копится до порога). Зоны риска и
зависимости → ревью всегда. Снимки лежат в `.git`, журнал ревью —
`~/.claude/review-log.tsv`, по нему `/rules-review` калибрует пороги.

## Сжатие контекста

База ставит `autoCompactWindow: 200000`: Claude Code сжимает разговор в сводку, когда
контекст доходит до 200 тыс. токенов. Без этого на моделях с окном 1 млн сжатие
происходит только у предела, и каждый ответ перечитывает сотни тысяч токенов, а
возврат в сессию после паузы больше часа перезаписывает их в кеш заново (на длинной
сессии это было 28% стоимости). После сжатия Claude Code сам подгружает CLAUDE.md,
память, 5 последних изменённых файлов и использованные навыки; что ещё сохранить в
сводке — раздел «Compact instructions» в CLAUDE.md. Своё значение: `/autocompact 300k`
(или `/autocompact auto` — по умолчанию модели); ваша настройка установщиком не меняется.

`/compact` — та же сводка вручную, можно с фокусом: `/compact сохрани решения по API`.
`/clear` — полностью новый разговор: для новой несвязанной задачи.

## Секреты

- `.env` и `.env.*` — `ask`: перед чтением или правкой Claude Code спрашивает
  разрешения. `.env.example` — без вопросов.
- Ключи и кошельки (`*.pem`, `*.key`, `~/.ssh`, Solana, Foundry, Ethereum) — `deny`:
  не читаются никогда; проект этот запрет не отменит.
- Приложение и тесты, которые сами загружают `.env`, работают как обычно.
- Это не песочница: скрипт, который сам открывает файл, правило не остановит —
  для этого песочница Claude Code (sandboxing).

graphify в базу не входит: он ставится в конкретный проект
(`graphify claude install` + `graphify hook install`) и сам пишет свою секцию и хуки.

Правило базы: сюда попадает только то, что верно для любого проекта.
Всё про конкретный стек — в проект. Заменили или убрали правило базы — строка
в `skills/project-setup/retired.md`, чтобы его копии нашлись в проектах.
